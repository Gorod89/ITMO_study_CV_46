# Как внести вклад

Спасибо за улучшение курса. Цель review — сохранить научную корректность, воспроизводимость и доступность для студентов с разным оборудованием.

## Рабочий процесс

1. Создайте issue с учебной проблемой, ожидаемым результатом и затрагиваемыми работами.
2. Создайте короткую ветку от `main`.
3. Вносите одну логическую группу изменений за pull request.
4. Выполните `make check`; для изменённого ноутбука дополнительно проверьте `Restart & Run All` в заявленном профиле.
5. Опишите, что изменилось для студента, преподавателя и воспроизводимости.

## Критерии нового материала

Новая лабораторная принимается только при наличии:

- измеримых learning outcomes и пререквизитов;
- оценки времени, RAM/VRAM и сетевых загрузок;
- `smoke`-профиля, выполняемого на CPU;
- фиксированного split и baseline;
- public tests и формата ожидаемых артефактов;
- рубрики, типичных ошибок и advanced track;
- карточек данных/моделей и проверки лицензий;
- ссылки на первоисточник, а не только на обзор или блог.

## Ноутбуки

- Выносите повторно используемую логику в Python-модули.
- Не добавляйте `pip install` без фиксированной версии внутрь ноутбука.
- Не используйте абсолютные пути, скрытое состояние ядра или test для подбора.
- Перед коммитом очищайте большие outputs, токены, персональные данные и локальные пути.
- TODO студента должен иметь контракт; public test не должен раскрывать решение.

## Безопасность оценивания

Не публикуйте ключи, эталонные решения, hidden tests, варианты экзамена и частные данные. Если такой материал попал в историю, не ограничивайтесь удалением текущего файла: уведомите владельца курса и перепишите историю до публикации.

## Научная актуализация

Для новой статьи укажите площадку и год, первичный источник, официальный код, лицензии кода/весов/данных, вычислительный бюджет и минимальный воспроизводимый эксперимент. Статус выбирается по [политике Stable/Candidate/Watchlist](docs/frontier-core-a.md#18-политика-актуализации-2026).
