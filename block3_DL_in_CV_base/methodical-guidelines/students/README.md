# Методические указания обучающимся. Блок 3 «Методы глубокого обучения в компьютерном зрении»

[← Блок 3](../README.md) · [Общие МУ](../../../docs/guidelines-students.md) · [РПД](../../../docs/rpd.md) · [Рубрики оценивания](../teachers-assessment/README.md)

Блок переводит вас от классических методов к глубокому обучению: современные свёрточные архитектуры и transfer learning, детекция и instance-сегментация, дообучение под собственную задачу. Ноутбуки являются заготовками: служебный код дан готовым, а оцениваемая реализация помечена `TODO` и описана проверяемым контрактом. Готовые решения вместо `TODO` не принимаются.

Общие требования к выполнению, сдаче и защите — в [общих МУ](../../../docs/guidelines-students.md).

## Измеримые результаты обучения

После блока обучающийся должен уметь:

1. адаптировать ImageNet-модель к новой классификационной задаче и различать linear probing, частичное и полное дообучение;
2. фиксировать seed и split, выбирать конфигурацию по validation и использовать test только для финальной оценки;
3. сопоставимо сравнивать модели по качеству, вычислительной стоимости и числу обучаемых параметров;
4. собирать pipeline детекции и instance-сегментации, рассчитывать подходящие метрики и анализировать FP/FN;
5. формулировать гипотезу до запуска и проводить контролируемую серию, меняя один фактор;
6. передавать конфигурации, журнал и артефакты так, чтобы запуск воспроизводился из чистого клона.

| ЛР2 ResNeXt | сокращённое стратифицированное подмножество | один GPU, 3–10 эпох |
| ЛР3–ЛР4 | 5–20 фиксированных изображений для проверки pipeline | один GPU желателен; оценка на согласованной выборке |
| ЛР5 YOLO | `CV_SMOKE=1`: `coco8.yaml`, CPU, 1 эпоха, 320 px | один GPU, Nano/Small, обычно 20–50 эпох |
| П3–П6 | уменьшенные подмножества, указанные в ноутбуке | один бесплатный GPU |

В ЛР1 и ЛР5 обучение намеренно выключено по умолчанию. После заполнения `TODO` включите public checks через `CV_PUBLIC_CHECKS=1`, затем обучение через `CV_RUN_TRAINING=1`. Smoke-режим проверяет целостность pipeline, но его метрики нельзя интерпретировать как оценку качества модели.

## Порядок выполнения

1. Работы выполняются в указанном порядке: ЛР1–ЛР2 формируют навык работы с классификационными моделями, ЛР3–ЛР5 — с детекционными.
2. Скопируйте ноутбук-заготовку, не изменяя оригинал; выполняйте задания в местах, отмеченных в ноутбуке.
3. Сначала выполните smoke-проход и public checks, затем запускайте полный эксперимент. В отчёте укажите версии библиотек, устройство, seed и commit.
4. Все сравниваемые конфигурации используют один split, одинаковый бюджет и правило выбора checkpoint. Гиперпараметры выбираются по validation; test используется один раз.
5. В ЛР5 датасет выбирается индивидуально и согласуется с преподавателем. Обязательны версия и лицензия набора, dataset card, `split_manifest.json`, гипотеза до запуска и вторая итерация с изменением ровно одного фактора.
6. Сдача — исполненный ноутбук, конфигурации и артефакты эксперимента; защита по [общей процедуре](../../../docs/guidelines-students.md#1-форма-выполнения-и-сдачи-работ).

## Минимальный комплект сдачи и критерии завершения

Для каждой лабораторной предоставьте:

- исполненный ноутбук без незаполненных обязательных `TODO`;
- конфигурацию запуска и фиксированный split либо его манифест;
- историю обучения и одинаковый набор метрик для всех сравниваемых конфигураций;
- таблицу результатов, визуализации и конкретный анализ ошибок;
- версии окружения, seed, устройство, время и ограничения вывода.

Код считается технически завершённым, если public checks проходят, все формы/типы выходов соблюдены, артефакты созданы по указанным путям, а smoke pipeline выполняется без ручного изменения скрытого состояния. Эксперимент считается методически завершённым, если baseline и серия сопоставимы, решения не подбирались по test, наблюдения отделены от интерпретаций и вывод не шире проведённых условий.

Public checks являются открытой обратной связью и не заменяют защиту. Преподаватель может применять отдельные hidden checks к тем же публичным контрактам; эталонные решения и закрытые тесты в студенческий репозиторий не входят.
