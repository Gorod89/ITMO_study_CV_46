# Методические указания преподавателям по оцениванию. Блок 3

[← Блок 3](../README.md) · [Единая модель оценивания](../../../docs/guidelines-teachers.md) · [Описания КИМ и ноутбуки](../students/README.md)

Все работы блока оцениваются по [единой 10-балльной рубрике](../../../docs/guidelines-teachers.md#1-модель-оценивания) (К1 реализация 0–3, К2 эксперимент 0–3, К3 анализ 0–2, К4 оформление и защита 0–2). Ниже — проверяемые элементы по лабораторным работам (ноутбуки #1–#5) и типичные ошибки.

## Привязка КИМ к индикаторам

| ЛР | Индикатор (уровень) | Что подтверждает |
|---|---|---|
| ЛР1 (ResNet) | DL-3.1 (С), DL-3.3 (Б) | применение предобученных моделей, оценка качества по стандартным метрикам |
| ЛР2 (ResNeXt) | DL-3.2 (С), DL-3.3 (Б) | дообучение с учётом особенностей архитектуры, настройка обучения |
| ЛР3 (Faster R-CNN) | DL-3.3 (Б), DL-3.2 (С) | двухстадийные детекторы, анализ ошибок детекции |
| ЛР4 (Mask R-CNN) | DL-3.3 (Б), DL-3.2 (С) | instance-сегментация, работа с масками и confidence |
| ЛР5 (YOLO) | DL-3.1 (С), DL-3.3 (Б) | полный цикл: данные → гипотеза → обучение → анализ → итерация |

## Проверяемые элементы (К1) по работам

**ЛР1:** предобработка соответствует весам модели (нормализация ImageNet); качество оценено на всём тестовом наборе, а не на подвыборке «удачных» примеров; confusion matrix построена и прокомментирована.

**ЛР2:** голова заменена корректно под число классов; разделены learning rate для backbone и головы (или обосновано иное); кривые обучения показывают отсутствие грубого переобучения; результат сравнён с ЛР1 (инференс без дообучения) — дообучение должно давать измеримый прирост.

**ЛР3:** данные приведены к формату детекции корректно (боксы, метки); порог confidence исследован, а не взят по умолчанию; анализ FP/FN выполнен на конкретных изображениях с объяснением причин.

**ЛР4:** маски извлечены и бинаризованы с исследованием порога; связь порога маски/confidence с качеством показана серией; сравнение с ЛР3 (детекция без масок) прокомментировано.

**ЛР5:** гипотеза сформулирована до обучения; датасет согласован и описан (объём, классы, разбиение); проведены минимум две итерации с изменением одного фактора; метрики (mAP) сравниваются между итерациями на одном валидационном наборе.

## Типичные ошибки

- нормализация входа не соответствует предобученным весам — «необъяснимо низкое» качество;
- дообучение оценивается на train-подмножестве; тестовые метрики отсутствуют;
- сравнение моделей при разных разрешениях входа или аугментациях;
- выводы о детекторе по 3–5 «показательным» картинкам без метрик по всему набору;
- в ЛР5 вторая итерация меняет сразу несколько факторов — прирост неинтерпретируем;
- игнорирование времени инференса при сравнении архитектур.

## Вопросы для защиты (примеры)

1. Покажите, где в коде заменяется голова сети. Что произойдёт, если этого не сделать?
2. Почему вы заморозили именно эти слои? Что показала бы разморозка всего backbone?
3. Объясните конкретный false positive из вашего анализа: что «увидела» модель?
4. Как изменится mAP при снижении порога confidence и почему?
5. Какую гипотезу проверяла ваша вторая итерация в ЛР5 и подтвердилась ли она?
