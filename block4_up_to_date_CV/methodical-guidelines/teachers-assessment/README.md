## Проверяемые элементы (К1–К2) по работам

**ЛР1 (DenseCRF):** в CRF передаются вероятности/логиты, а не бинарная маска; сравнение baseline / spatial-only / spatial+bilateral на одном наборе; качество области (IoU/Dice) и границы (boundary F-score с зафиксированным радиусом) анализируются раздельно; показаны случаи исчезновения мелких компонент.

**ЛР2 (ViT/ConvNeXt):** сопоставимое сравнение (одинаковые split, разрешение, аугментации, критерий checkpoint); linear probe отделён от partial fine-tuning; учтены trainable parameters, время и память; embeddings при замороженном backbone кэшируются.

**ЛР3 (метрическое обучение):** query/gallery без self-match, у каждого query есть relevant; baseline на предобученных признаках до обучения; корректный mining (без диагонали); Recall@K/mAP/MRR посчитаны по validation, выбор checkpoint не по test; top-K проанализирован визуально.

**ЛР4 (мультимодальный поиск):** один индекс gallery для всех режимов (text/image/hybrid); запросы сгруппированы по intent с перефразировками; исследована чувствительность к формулировке; α гибридного запроса не подбирается по test; эмбеддинги нормализованы до слияния.

**ЛР5 (сжатие):** бенчмарк с warmup, повторами и синхронизацией GPU; указаны provider, потоки CPU, batch size; после экспорта/квантования проверена численная близость и метрики качества; calibration-набор не пересекается с test; построен Парето-фронт качество–latency–размер.

**ЛР6 (генерация синтетики):** опорный набор кадров с зафиксированными факторами; серии с одинаковыми исходниками/prompt/seed при изменении одного параметра (denoise, вариант модели); оценка по трём осям (сохранение домена, выполнение инструкции, артефакты); вывод о пригодности для downstream-задачи сделан с явными ограничениями (или проведена downstream-проверка).

## Типичные ошибки (снижают К2 до 0–1)

- отсутствие baseline или его изменение после начала серий;
- одновременное изменение нескольких факторов в «сравнении»;
- выбор параметров/checkpoint/промптов по test;
- журнал экспериментов отсутствует или невоспроизводим (нет seed, версий, конфигураций);
- средние метрики без анализа отказных случаев;
- в ЛР5 — «ускорение» без честного бенчмарка (нет warmup/синхронизации);
- в ЛР6 — только удачные генерации, серии не сохранены.
