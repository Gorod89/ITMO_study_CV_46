# Общие методические указания обучающимся

[← К описанию курса](index.md) · [РПД](rpd.md) · [МУ преподавателям](guidelines-teachers.md)

Документ содержит общие требования ко всем лабораторным и домашним работам дисциплины. Специфические указания к работам каждого блока находятся в разделах `blockN_*/methodical-guidelines/students/`.

## 1. Форма выполнения и сдачи работ

1. Работа выполняется в Jupyter-ноутбуке (или, по согласованию с преподавателем, в виде скриптов с отчётом в Markdown).
2. Сдаваемый ноутбук должен **исполняться сверху вниз без ошибок** после перезапуска ядра (`Restart & Run All`). Работы, которые не воспроизводятся, возвращаются на доработку без оценивания содержания.
3. В начале ноутбука указываются: ФИО, группа, номер работы, используемые датасеты и их источники.
4. Зависимости берутся из корневого `pyproject.toml` и lock-файла. Ячейки с нефиксированным `pip install` в сдаваемой версии не допускаются.
5. Фиксируйте seed, split, версии данных/весов, commit и provider — результаты должны быть воспроизводимы.
6. Работа сдаётся через репозиторий/LMS в срок, установленный преподавателем; защита проходит очно или онлайн в форме короткого доклада (5–7 минут) с ответами на вопросы.

## 2. Методика эксперимента

Во всех работах курса используется одна инженерная логика:

```
данные → baseline → контролируемая серия → метрики и артефакты → анализ ошибок → ограниченный вывод
```

- **Эксперимент** — не отдельный запуск, а воспроизводимая конфигурация: версия данных и разбиение, модель и веса, преобразования входа, параметры, seed, версии библиотек, метрики, пути к артефактам.
- **Baseline** — минимально разумная конфигурация, относительно которой оцениваются изменения. Baseline не изменяется после начала основной серии.
- **Validation и test.** Validation используется для выбора (checkpoint, параметров, порога). Test применяется один раз после фиксации решения; повторный подбор по test делает оценку оптимистичной.
- **Контролируемая серия.** В простой серии изменяется один фактор. Если одновременно изменить модель, разрешение и аугментации — невозможно определить причину результата.
- **Наблюдение ≠ вывод.** Разделяйте измеренный факт, предполагаемую причину и вывод в пределах проверенных условий.

## 3. Требования к отчётной части

Каждая работа завершается разделом с результатами, который включает:

1. сводную таблицу экспериментов (конфигурация → метрики → время/ресурсы);
2. визуализации (примеры предсказаний, кривые обучения — где применимо);
3. анализ ошибок: не только средние метрики, но и характерные неудачные случаи;
4. выводы, отделённые от наблюдений, с указанием ограничений;
5. ответы на контрольные вопросы работы (если предусмотрены).

## 4. Справочник основных метрик

| Задача | Метрики |
|---|---|
| Классификация | accuracy, macro F1, per-class recall, confusion matrix |
| Детекция | mAP (по порогам IoU), precision/recall |
| Сегментация | IoU, Dice, boundary F-score |
| Поиск (retrieval) | Recall@K, Precision@K, mAP, MRR |
| Производительность | mean/median/p95 latency, throughput, peak memory, model size |

## 5. Использование сторонних материалов и LLM

- Использование открытых датасетов, предобученных моделей и фрагментов документации допускается **с указанием источника**.
- Использование LLM-ассистентов допускается как инструмент (объяснение ошибок, черновики кода), но: (а) вы обязаны понимать и уметь объяснить каждый фрагмент сдаваемого кода; (б) использование раскрывается в `AI_USAGE.md` по [шаблону](https://github.com/Gorod89/ITMO_study_CV_46/blob/main/templates/AI_USAGE.md); (в) результат проверяется тестами и первичными источниками. На защите оценивается ваше понимание и качество проверки.
- Прямое заимствование чужих решений без переработки и указания источника — основание для незачёта работы.

## 6. Чек-лист перед сдачей

- [ ] Ноутбук исполняется сверху вниз без ошибок.
- [ ] Split данных фиксирован, test не использовался для настройки.
- [ ] Baseline рассчитан, изменяемые факторы серий указаны.
- [ ] Seed и версии записаны.
- [ ] Заполнены data/model card и `AI_USAGE.md`, если применимо.
- [ ] Есть сводная таблица результатов и анализ ошибок.
- [ ] Наблюдения отделены от интерпретаций, ограничения указаны.
- [ ] Источники данных, моделей и заимствованного кода указаны.

## 8. Критерии оценивания

Все работы оцениваются по единой 10-балльной аналитической рубрике (реализация — эксперимент — анализ — оформление и защита); подробности и специфические критерии каждого КИМ — в [общих указаниях преподавателям](guidelines-teachers.md) и разделах `teachers-assessment` блоков. Вы имеете право ознакомиться с рубрикой до выполнения работы и получить обратную связь по каждому критерию после проверки.
