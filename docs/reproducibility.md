## Контракт запуска

Каждая лабораторная имеет два режима:

- `smoke` завершает весь путь данных и сохраняет артефакты на CPU за минуты;
- `full` проверяет учебную гипотезу на полном наборе и может требовать GPU.

Smoke подтверждает работоспособность интерфейса, но не доказывает качество модели и не заменяет статистически достаточный эксперимент.

## Обязательные поля эксперимента

Один запуск хранит:

```json
{
  "experiment_id": "lab3-linear-probe-seed42",
  "git_commit": "abcdef0",
  "data_id": "cifar10",
  "data_version": "1",
  "split_id": "official",
  "model_id": "resnet18",
  "weights_id": "torchvision-default",
  "config": "configs/smoke.yaml",
  "seed": 42,
  "device": "cpu",
  "provider": "pytorch",
  "metrics": {"macro_f1": 0.0},
  "artifacts": ["outputs/confusion_matrix.png"]
}
```

Журнал JSONL дополняется новой строкой; уже опубликованный запуск не редактируется. Конфигурация, код и артефакты должны однозначно связываться с таблицей в отчёте.

## Научный протокол

1. Зафиксировать вопрос и гипотезу до просмотра test.
2. Зафиксировать данные, split, baseline и критерий выбора checkpoint.
3. В простой серии менять один фактор.
4. Подбирать пороги и параметры только на validation.
5. После фиксации решения один раз применить test.
6. Для стохастического обучения использовать не менее трёх seed либо явно пометить вывод как smoke-only.
7. Показать разброс/доверительный интервал, ошибки по подгруппам и неудачные случаи.
8. Ограничить вывод проверенными данными, моделями и бюджетом.

## Release gate лабораторной

- [ ] Чистый клон и locked-окружение.
- [ ] Нет абсолютных путей, токенов, приватных данных и скрытого состояния.
- [ ] Public tests проходят.
- [ ] Smoke выполняется без закрытых ресурсов.
- [ ] Полный режим имеет конфигурацию и вычислительный бюджет.
- [ ] Датасет и веса имеют идентификаторы, источник и условия использования.
- [ ] README содержит learning outcomes, baseline, артефакты, рубрику и advanced track.
- [ ] Независимый проверяющий воспроизвёл ключевую таблицу одной командой.
