Открытый русскоязычный курс для подготовки ML-инженеров, способных спроектировать, измерить, воспроизвести и критически оценить систему компьютерного зрения. Курс идёт от классической обработки изображений и геометрии к transfer learning, детекции, сегментации, мультимодальным и генеративным моделям, оптимизации инференса и анализу рисков.

> Состояние релиза: `v1.0.0-rc1`, техническая апробация. Статус «production-ready» присваивается только после CI, запуска smoke-наборов из чистого клона, методической экспертизы и пилота со студентами.

## Быстрый старт

Требуются Git и Python 3.11 или 3.12. Рекомендуемый менеджер окружения — [uv](https://docs.astral.sh/uv/).

```bash
git clone https://github.com/Gorod89/ITMO_study_CV_46.git
cd ITMO_study_CV_46
make setup
make test
make smoke
```

Команды не загружают большие датасеты и веса. Тяжёлые лабораторные запускаются явно после выбора профиля окружения; подробности — в [руководстве по установке](docs/setup.md) и [протоколе воспроизводимости](docs/reproducibility.md).

## Результаты обучения

После курса студент умеет:

1. выбирать классический или нейросетевой подход под задачу и ограничения;
2. строить честный протокол `данные → baseline → контролируемая серия → метрики → анализ ошибок → ограниченный вывод`;
3. предотвращать утечки данных и отделять validation от финального test;
4. адаптировать предобученные представления через linear probe, частичное и полное дообучение;
5. оценивать классификацию, детекцию, сегментацию, retrieval и производительность;
6. проектировать CPU/GPU-инференс и измерять компромисс «качество — задержка — память»;
7. документировать данные, модель, риски, ограничения и использование LLM;
8. воспроизводить ключевой результат одной командой из чистого клона.

## Два режима воспроизведения

- `open smoke` — малые открытые или процедурные данные, CPU, без секретов и закрытых весов; проверяет полный интерфейс конвейера.
- `full` — полные датасеты и GPU-профили; применяется для учебных экспериментов и не входит в обязательный CI.

Каждая новая работа должна иметь измеримые результаты обучения, вычислительный бюджет, фиксированный split, baseline, public tests, ожидаемые артефакты, рубрику, типичные ошибки и advanced track. Ноутбук служит интерфейсом эксперимента; повторно используемая логика размещается в Python-модулях.

## Оценивание и безопасность

В публичном репозитории находятся задания, рубрики, тренировочные вопросы и public tests. Ключи, эталонные решения, hidden tests и экзаменационные генераторы должны храниться в отдельном закрытом преподавательском репозитории. Публичная история этого репозитория не должна содержать такие материалы.

Совпадение решений является сигналом к индивидуальной проверке, а не автоматическим доказательством нарушения. Использование LLM разрешено при раскрытии в `AI_USAGE.md`, проверке результата и способности объяснить вклад инструмента.
